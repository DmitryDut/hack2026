# Playbook: «А теперь поменяйте вот это»

Как выполнить типовые правки **без изменения кода и без перезапуска**. Правки делает оператор (`operator` / `demo`) в разделе **«Администрирование»** (плитки: тарифы и градации, сроки, паспорт трафика, поля услуги; «Расширенно» — схемы и новые типы), результат смотрим под партнёром (`mts-link-1` / `demo`). Автотесты каждой правки — в колонке «Проверено». Время: секундомером не измерялось; каждая правка — одна форма или одна строка в YAML.

## Ограничения
- Схемы встроенных типов нельзя лишать базовых полей (редактор не даст); новые поля встроенных типов хранятся в `extra`.
- Новые типы (C-04) не связаны с другими типами и не попадают в JSON для PX (TD-026).
- Список вкладок в `process.yaml` должен соответствовать шаблонам `_tab_<id>.html`: добавить новую по-настоящему «свою» вкладку — работа для разработчика.
- Правки YAML применяются после «Перечитать YAML-конфиг» (раздел «Схемы») или при перезапуске.

## Подсказка для показа
Порядок на демо: C-01 → C-02 → C-03 → C-04 → C-05 (по 1–2 минуты каждая); C-06 и C-07 — если попросят про процесс и JSON.
