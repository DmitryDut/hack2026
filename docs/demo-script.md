# Сценарий демо (≈6–8 минут; он же приёмочный тест — `tests/test_demo_flow.py`)

Данные: `docs/source/zadanie/tz/*/test_data`. Перед началом — `make reset` (сид: партнёр `mts-link-1`, «Link ВКС», справочники).

## Часть 1. «Первое демо» — рабочая версия
1. **Витрина → конфигуратор.** Открываем витрину PX, «Конфигурировать сервисы QoS» → страница конфигуратора во фрейме; `partner_id` в шапке из токена, руками не вводился [EMB-1]. (Мусорный токен → страница ошибки [EMB-2].)
2. **Сервисы и сигнатуры.** «Link ВКС» (из сида) + «Link Чаты»; добавляем сигнатуру `10.10.2.10 / api.mts-link.ru / 8443 / HTTPS`. Порт `70000` отклоняется, дубликат даёт 409 [DATA-5, DATA-6].
3. **Профиль, срок и цена.** Platinum + 12H → цена 30 000 ₽/мес; можно завести второй вариант (Gold, 10 000) и сравнить [PROC-2, PROC-4]. Подтверждаем цену [PROC-3].
4. **JSON для PX.** `GET /api/v1/partners/mts-link-1/export` — структура как в эталоне; витрина получает его через `postMessage` и показывает карточку «Партнёр подключён» с SLA [EXP-1, EMB-3, MOCK-3].
5. **Песочница.** «Начать тест» → построчная проверка; 4-я сигнатура (`media2.mts-link.ru:5005`) падает «RTP-поток не отвечает» → Failed [SBX-2…SBX-4]. Правка сигнатуры сбрасывает прогон в Draft, запись в журнале [SBX-5].
6. **Исправление и запуск.** Порт 5006 → новый прогон, все success, подтверждаем → Passed → «Старт коммерческой эксплуатации» → `session_id` от мока → Applied [SBX-7]. Правка в Applied отклонена [SBX-6].
7. **Абонент.** Подключаем сервис абоненту по номеру → карточка абонента: сервис, профиль, срок, таймлайн [SUB-1…SUB-3].
8. **Наблюдаемость.** Журнал событий, журнал вызовов моков, трассировка 17 реплик [SBX-8, TRC-1, TRC-2].

## Часть 2. «А теперь поменяйте вот это» — кульминация [NFR-1]
Каждый пункт — правка без изменения кода и без рестарта; замеряем время:
1. Новый уровень «Diamond 200 Мбит/с» (запись в справочнике) → появляется в выборе профиля и в цене (4.0).
2. В `signature` поле `ipv6`, `uri` необязателен → обновить страницу, формы изменились, старые записи читаются [CORE-5, CORE-8].
3. В `service` поле `sla_percent` (99–99.999): 99.5 → 201, 50 → 422 [CORE-3].
4. Новая сущность «Мониторинг» целиком из админки: раздел и CRUD появились [CORE-7].
5. Изменить формулу цены или множители → цена пересчитана.
6. Поменять порядок шагов процесса.
7. Добавить поле в JSON для PX (маппинг экспорта).

Запуск: `make reset && make dev`.
