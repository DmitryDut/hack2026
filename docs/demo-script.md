# Сценарий демо (≈8 минут; он же приёмочный тест — `tests/test_demo_flow.py`)

Подробные шаги, ветки и хронометраж — `docs/scenarios.md` (S-01…S-09, §5 «Сквозное демо»); экраны — `docs/ui/`. Данные: `docs/source/zadanie/tz/*/test_data`. Перед началом — `make reset` (сид: партнёр `mts-link-1`, услуги «Link ВКС» и «Link Чаты», тарифы, учётки `mts-link-1`/`demo`).

## Часть 1. «Первое демо» — рабочая версия
0. **Витрина PX (по желанию).** `/px-showcase` → «Конфигурировать сервисы QoS» открывает кабинет в iframe по подписанному токену; «Предложение» → «Отправить в витрину PX» рисует карточку «Партнёр подключён» с ценами. Флоу из диаграммы задания: `/qos_platform/landing` (трассировка 17 реплик).
1. **Вход.** `/login` → `mts-link-1` / `demo` (или из витрины PX: iframe по токену без формы); в шапке кабинета партнёр «MTS Link». Мусорный токен → страница ошибки [AUTH-1…AUTH-3, EMB-2].
2. **Услуга и данные для QoS.** Добавляем «Link Записи» и сигнатуру `10.10.2.10 / api.mts-link.ru / 8443 / HTTPS`; порт `70000` отклоняется, дубликат — 409; удаляем лишнее [CAB-2, DATA-5, DATA-6].
3. **Тариф и стоимость.** Для «Link ВКС»: Платина, 12 ч → `100 × 100 × 3.0 × 1.0 = 30 000 ₽/мес`; смена срока на 24 ч → 51 000; таблица тарифов с ценой по каждому; подтверждаем цену [CAB-3, PROC-2, PROC-3].
4. **Предложение и JSON в PX.** «Стоимость и предложение»: итог 47 000 ₽/мес (с «Link Чаты»: Золото 24 ч = 17 000), сравнение вариантов, JSON, «Отправить в витрину PX» → карточка «Партнёр подключён» [CAB-4, EXP-1, EMB-3, MOCK-3].
5. **Тестирование.** Построчная проверка; сигнатура `media2.mts-link.ru:5005` падает «RTP-поток не отвечает» → «Тест не пройден»; правка порта на 5006 сбрасывает тест; новый прогон — «Тест пройден» [SBX-2…SBX-5].
6. **Включение приоритета.** «Включить приоритет» → `session_id` от мока; **⚡ Трафик приоритизирован**: баннер и строка в кабинете, панель (тариф, срок, сигнатуры), витрина; правка сигнатур запрещена [SBX-6, SBX-7, SBX-11].
7. **Абонент.** Подключаем услугу номеру `+7 916 123 00 01` → карточка абонента с плашкой ⚡ и таймлайном [SUB-1…SUB-3].
8. **Наблюдаемость.** Журнал событий, внешние вызовы (запрос/ответ), трассировка 17 реплик (флоу диаграммы) [SBX-8, TRC-1, TRC-2].

## Часть 2. «А теперь поменяйте вот это» — кульминация [NFR-1]
Правки делает **оператор** (`operator` / `demo`): справочники — `/entities`, схемы — `/admin/schemas`; результат смотрим под партнёром. Работают C-01…C-05 (проверены `tests/test_schema_change.py`), C-06 и C-07 — позже (PLAN P1.7).
Каждый пункт — правка без изменения кода и без рестарта (YAML — с «Перечитать конфиг»); замеряем время:
1. Новый тариф «Бриллиант+ 300 Мбит/с» (запись в справочнике) → появляется в таблице тарифов, цена `300 × 100 × 5.0 = 150 000 ₽/мес` (C-01).
2. В `signature` поле `ipv6`, `uri` необязателен → формы изменились, старые записи читаются (C-02).
3. В `service` поле `sla_percent` (99–99.999): 99.5 → принято, 50 → ошибка (C-03).
4. Новая сущность «Мониторинг» целиком из админки (C-04).
5. Изменить ставку 100 → 120 или скидку за срок (коэффициент 24 ч) → цена пересчитана (C-05).
6. Поменять условия доступа вкладок («тест до подтверждения цены») (C-06).
7. Добавить поле в JSON для PX (C-07).

Запуск: `make reset && make dev`.
