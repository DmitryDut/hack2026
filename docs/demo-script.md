# Сценарий демо (он же приёмочный тест — `tests/test_demo_flow.py`)

1. **Вход из PX.** Открываем `/qos_platform/landing?partner_id=partners-1` (режим `?embed=1` — как в iframe). Видим партнёра «MAX» в статусе `registered`.
2. **Сервисы и сигнатуры.** Создаём «Link ВКС» и «Link Чаты». Для каждого добавляем сигнатуры `{IPv4, URI, port, protocol}`, например `203.0.113.10:443/HTTPS`, `203.0.113.11:3478/UDP`. Неверный порт или протокол вне справочника отклоняется. Статус `configuring`.
3. **QoS-профили и Duration.** Из справочника выбираем профили (Gold, Silver…) и Duration. Duration больше `max_duration` профиля отклоняется.
4. **Оффер.** «Отправить в PX»: показываем JSON по спецификации PX и полученную цену. Партнёр подтверждает цену → `offer_confirmed`.
5. **Песочница.** Построчный проход по сигнатурам. Одну строку отмечаем «не прошла» → возврат в `configuring`, правим сигнатуру, повторный прогон проходит полностью.
6. **Активация.** `active`; в журнале внешних вызовов виден эмулированный запрос в GSMA QoD APIgw с CAMARA-подобным payload.
7. **Абонент.** Подключаем активный сервис абоненту по MSISDN → карточка абонента: сервис, профиль, Duration, таймлайн событий. Эмулированный запрос в сеть виден в журнале.
8. **Гибкость.** Правим `config/qos_profiles.yaml` (новый профиль) и `config/protocols.yaml` (новый протокол), перезапускаем — новое значение доступно в UI и валидации без изменения кода.

Запуск: `make reset && make dev`.
