# Конфигуратор

Пути: `/embed?token=…` (вход), затем `/configurator/services|profiles|offer|sandbox|activation`. Шаги и их порядок — `config/process.yaml`. Требования: DATA-4…DATA-7, PROC-1…PROC-5, EXP-1, SBX-1…SBX-10, SUB-1, NFR-3, NFR-7. Сценарии: S-02…S-06, N-04…N-10.

## Каркас экрана
```text
┌──────────────────────────────────────────────────────────────────────────┐
│ QoD management │ Партнёр: MTS Link (mts-link-1) — из токена              │
├──────────────────────────────────────────────────────────────────────────┤
│ ① Сервисы ─ ② Профиль и срок ─ ③ Предложение ─ ④ Песочница ─ ⑤ Запуск   │
│   (текущий шаг подсвечен; недоступные серым, при наведении — причина)    │
├──────────────────────────────────────────────────────────────────────────┤
│ {{ содержимое шага }}                                                    │
├──────────────────────────────────────────────────────────────────────────┤
│ ▸ Журнал событий    ▸ Внешние вызовы                                     │
└──────────────────────────────────────────────────────────────────────────┘
```
Блокировки (`gates`): шаг 4 доступен, только когда цена подтверждена (предложение `confirmed`); шаг 5 — когда сервис в статусе `passed` (или `applied`).
Подсказка недоступного шага: «Сначала подтвердите цену на шаге ③».

## Шаг ① Сервисы и сигнатуры — `/configurator/services`

### 2.1 Список сервисов
```text
Сервисы партнёра                                          [+ Добавить сервис]
┌───────────────────────────────────────────────────────────────────────────┐
│ Link ВКС      Видеоконференцсвязь MTS Link     4 сигнатуры   черновик      │
│               [Сигнатуры]  [Изменить]  [Удалить]                          │
│ Link Чаты     Чаты MTS Link                    1 сигнатура   черновик      │
│               [Сигнатуры]  [Изменить]  [Удалить]                          │
└───────────────────────────────────────────────────────────────────────────┘
                                                           [Далее: профиль →]
```
- Статус сервиса — состояние песочницы (`черновик`, `тестируется`, `пройден`, `ошибка`, `запущен`).
- Пусто: «Сервисов пока нет. [+ Добавить сервис]».
- Удаление — подтверждение «Удалить сервис и его сигнатуры?» (каскад).

### 2.2 Форма сервиса (форма строится по схеме `service`; рендерер — `SPEC.md` §7)
```text
Новый сервис
Название*        [Link Записи____________]
Описание         [____________________________]
                 [Сохранить]  [Отмена]
```
Поля `partner_ref`, `qos_profile_code`, `duration_code` на этом шаге скрыты (задаются на шаге ②). Если схему расширят (например, `sla_percent`), поле появится само.

### 2.3 Сигнатуры сервиса «Link ВКС»
```text
Сигнатуры сервиса «Link ВКС»                              [+ Добавить сигнатуру]
┌─────┬─────────────┬────────────────────────┬──────┬──────────┬─────────────┐
│ №   │ IPv4        │ URI                    │ Порт │ Протокол │             │
├─────┼─────────────┼────────────────────────┼──────┼──────────┼─────────────┤
│ sig-1│ 10.10.1.5  │ vcs.mts-link.ru        │ 443  │ HTTPS    │ [✎] [🗑]    │
│ sig-2│ 10.10.1.6  │ media.mts-link.ru      │ 5004 │ RTP      │ [✎] [🗑]    │
│ sig-3│ 10.10.1.7  │ api.mts-link.ru        │ 8443 │ HTTPS    │ [✎] [🗑]    │
│ sig-4│ 10.10.1.8  │ media2.mts-link.ru     │ 5005 │ RTP      │ [✎] [🗑]    │
└─────┴─────────────┴────────────────────────┴──────┴──────────┴─────────────┘
```
Форма сигнатуры (по схеме `signature`):
```text
IPv4*      [10.10.2.10____]
URI*       [api.mts-link.ru____]
Порт*      [70000__]            ⚠ Порт должен быть от 1 до 65535
Протокол*  [HTTPS ▼]            (список из справочника протоколов)
           [Сохранить]  [Отмена]
```
Ошибки (DATA-5, DATA-6; тексты — допущение):
| Случай | Где | Текст |
|---|---|---|
| порт вне 1–65535 | под полем | «Порт должен быть от 1 до 65535» |
| IPv4 неверный | под полем | «Неверный адрес IPv4» |
| протокол не из справочника | под полем | «Недопустимый протокол» |
| дубликат | плашка | «Такая сигнатура уже есть у сервиса» (409) |
Если сервис в `in_testing`/`passed`/`failed` — при сохранении предупреждение: «Изменение сбросит прогон песочницы» `[Изменить и сбросить] [Отмена]`. В `applied` кнопки `[✎] [🗑]` недоступны, подсказка: «Сервис запущен; изменения запрещены. Сброс — через оператора».

## Шаг ② Профиль и срок — `/configurator/profiles`

### 2.4 Назначение
```text
Профиль и срок для сервисов
┌────────────────────────────────────────────────────────────────────────────┐
│ Link ВКС                                                                   │
│ Профиль качества                                                           │
│ ┌ Bronze ───┐ ┌ Silver ───┐ ┌ Gold ─────┐ ┌ Platinum ─┐ ┌ Diamond ──┐    │
│ │ 10 Мбит/с │ │ 30 Мбит/с │ │ 50 Мбит/с │ │100 Мбит/с │ │200 Мбит/с │    │
│ │ SLA 99.0 %│ │ SLA 99.5 %│ │ SLA 99.9 %│ │SLA 99.95 %│ │SLA 99.99 %│    │
│ │ ×1.0      │ │ ×1.5      │ │ ×2.0      │ │ ×3.0 ◉    │ │ ×4.0      │    │
│ └───────────┘ └───────────┘ └───────────┘ └───────────┘ └───────────┘    │
│ Срок действия приоритета   [12 ч ▼]   (1 ч / 6 ч / 12 ч / 24 ч / 72 ч)   │
│ Цена: 100 × 100 ₽ × 3.0 = 30 000 ₽/мес                                     │
├────────────────────────────────────────────────────────────────────────────┤
│ Link Чаты  …   профиль: ( ) не выбран                                      │
└────────────────────────────────────────────────────────────────────────────┘
                                          [← Назад]   [Далее: предложение →]
```
- Карточки профилей строятся из справочника `qos_profile` (только `ACTIVE`; прочие скрыты или серые с пометкой «недоступен»). Добавленный профиль появляется без правки кода.
- Цена пересчитывается сразу при выборе (формула из `pricing.yaml`, значения из справочника).
- Если выбрано не всё: `[Далее]` недоступна, рядом «Выберите профиль и срок для: Link Чаты».
- Изменение назначения у сервиса вне `draft` — то же предупреждение о сбросе, что в 2.3.

## Шаг ③ Предложение и цена — `/configurator/offer`

### 2.5 Варианты предложения
```text
Варианты предложения                                         [+ Новый вариант]
┌──────────────────────────────────────────────────────────────────────────┐
│ (•) Базовый                        итого 40 000 ₽/мес         черновик   │
│     Link ВКС  Platinum 12 ч  30 000 │ Link Чаты  Gold 24 ч  10 000       │
│ ( ) Экономный                      итого 15 000 ₽/мес         черновик   │
│     Link ВКС  Silver 12 ч  4 500 … (пример)                              │
└──────────────────────────────────────────────────────────────────────────┘
[Сравнить варианты]
```
Сравнение — таблица «сервис × вариант» с ценой и итогом; выбранный вариант отмечен. Пример вариантов — иллюстрация; цену каждого сервиса считает `pricing.yaml`.

### 2.6 Детали выбранного варианта и подтверждение
```text
Вариант «Базовый»
┌──────────────┬───────────┬───────┬─────────────┬────────────────┐
│ Сервис       │ Профиль   │ Срок  │ Сигнатур    │ Цена           │
├──────────────┼───────────┼───────┼─────────────┼────────────────┤
│ Link ВКС     │ Platinum  │ 12 ч  │ 4           │ 30 000 ₽/мес   │
│ Link Чаты    │ Gold      │ 24 ч  │ 1           │ 10 000 ₽/мес   │
├──────────────┴───────────┴───────┴─────────────┼────────────────┤
│                                          Итого │ 40 000 ₽/мес   │
└────────────────────────────────────────────────┴────────────────┘
▸ JSON для PX (предпросмотр)
┌ {                                                                   ┐
│   "schema_version": "0.1", "partner_id": "mts-link-1", …            │
└─────────────────────────────────────────────────────────────────────┘
[Отправить в витрину]      [Подтвердить цену]
```
- `[Подтвердить цену]` → вариант и его сервисы получают статус «подтверждено»; шаг ④ становится доступным. Недоступна, если у сервиса нет профиля или срока: «У сервиса Link Чаты не выбран профиль».
- `[Отправить в витрину]` → `postMessage(qod:export)`; в режиме вкладки — результат показывается здесь же.
- `JSON для PX` — предпросмотр экспорта (`docs/px-json-proposal.md`); поля соответствуют `config/px_payload.yaml`.
- Правка назначения после подтверждения возвращает вариант в «черновик»: «Цена сброшена, подтвердите заново».

## Шаг ④ Песочница — `/configurator/sandbox`

### 2.7 До начала теста (статус `draft`)
```text
Песочница · Link ВКС                                  Статус: Черновик
 Черновик ─► Тестируется ─► Пройден ─► Запущен      (степпер, текущий жирным)

 Сигнатур к проверке: 4         Профиль: Platinum · 12 ч · цена подтверждена ✓
 [Начать тест]
```
- Список сервисов — переключатель сверху («Link ВКС ▾ / Link Чаты»); у каждого свой прогон.
- `[Начать тест]` недоступна без подтверждённой цены: «Подтвердите цену на шаге ③».

### 2.8 Идёт тест (`in_testing`)
```text
Песочница · Link ВКС                                  Статус: Тестируется
 Черновик ─► [Тестируется] ─► Пройден ─► Запущен

┌────┬──────────────────────────────┬──────────┬───────────┬──────┬─────────┐
│ №  │ Сигнатура                    │ Профиль  │ Результат │ Подтв│         │
├────┼──────────────────────────────┼──────────┼───────────┼──────┼─────────┤
│ 1  │ 10.10.1.5 vcs…:443 HTTPS     │ Platinum │ ✓ успех   │ [x]  │         │
│ 2  │ 10.10.1.6 media…:5004 RTP    │ Platinum │ ✓ успех   │ [ ]  │         │
│ 3  │ 10.10.1.7 api…:8443 HTTPS    │ Platinum │ … ожидает │ [▒]  │[Проверить]│
│ 4  │ 10.10.1.8 media2…:5005 RTP   │ Platinum │ … ожидает │ [▒]  │[Проверить]│
└────┴──────────────────────────────┴──────────┴───────────┴──────┴─────────┘
 Подтверждено 1 из 4        Срок: 12 ч
```
- `[Проверить]` вызывает мок валидации; на время вызова — «Проверка…» (имитация 300–800 мс).
- Галка «Подтв» доступна только после `✓ успех`; снять её можно.
- Все строки `✓` и подтверждены → статус «Пройден» автоматически.
- Порядок проверки произвольный.

### 2.9 Ошибка проверки (`failed`)
```text
Песочница · Link ВКС                                  Статус: Ошибка теста
 Черновик ─► Тестируется ─► ✗ Не пройден

│ 4  │ 10.10.1.8 media2…:5005 RTP   │ Platinum │ ✗ ошибка  │ [▒]  │          │
 ⚠ BEARER_TIMEOUT: RTP-поток не отвечает: таймаут установки dedicated bearer
   для media2.mts-link.ru:5005
 Остальные строки не проверяются, пока прогон не начат заново.
 [Вернуться к конфигурированию]
```
- Прогон завершается сразу при первой ошибке.
- `[Вернуться к конфигурированию]` → статус «Черновик», шаги прогона удаляются, открывается шаг ①.

### 2.10 Сброс из-за правки
```text
⚠ Прогон сброшен из-за изменения сигнатуры sig-4 (порт 5005 → 5006).
  Статус: Черновик. Начните тест заново.                        [Начать тест]
```
Плашка вверху экрана после правки на шаге ①. Запись в «Журнале событий» (`run_reset`, `signature_updated`).

### 2.11 Тест пройден (`passed`)
```text
Статус: Пройден ✓       4 из 4 проверено и подтверждено
[Перейти к запуску →]
```

### 2.12 Журнал событий (раскрывающаяся панель)
```text
▾ Журнал событий · Link ВКС
 12:05:10  run_started        шагов 4: draft → in_testing
 12:05:14  step_checked       sig-1 успех
 12:05:15  step_confirmed     sig-1
 …
 12:05:40  run_failed         step_error: in_testing → failed
 12:05:55  run_reset          signature_modified (sig-4): failed → draft
 12:05:55  signature_updated  sig-4 порт 5005 → 5006
```
Показывает сырые имена событий (для сверки с `expected_event_log.json`) и понятный текст рядом.

## Шаг ⑤ Запуск — `/configurator/activation`

### 2.13 Старт эксплуатации
```text
Запуск · Link ВКС                                  Статус: Пройден ✓
Будет передано в GSMA QoD APIgw (мок):
  профиль PLATINUM · срок 12 ч · сигнатур 4
  ▸ Показать запрос (JSON)
[Старт коммерческой эксплуатации]
```
- Ошибка: IP больше 16 → «Для запуска допускается не более 16 уникальных IP-адресов (сейчас 18)» (CAMARA).
- Запрос раскрывается в JSON с блоками `camara` и `pfd` (`SPEC.md` §9).

### 2.14 После запуска (`applied`)
```text
Статус: Запущен ✓                                     session_id: qod-session-8f3a2b
Начало 12:07:01 · Окончание 00:07:01 (12 ч)
▸ Ответ APIgw (JSON)

Подключить сервис абоненту
Номер абонента*  [+7 916 123 00 01___]   [Подключить]
Подключено абонентов: 0
```
- Блок «Подключить сервис абоненту» — см. `03-subscriber.md`.
- Для оператора внизу: `[Сбросить в черновик (оператор)]` с подтверждением `confirm` — только в кабинете оператора, не в iframe партнёра.

## Что проверить при ревью
1. Порядок шагов (особенно: профиль отдельным шагом после сервисов) и названия вкладок.
2. Нужен ли выбор профиля **на каждый сервис** отдельно (сейчас да) или один на предложение.
3. «Варианты предложения» — нужны ли в демо или достаточно одного предложения (PROC-4 — из рекомендаций MVP).
4. Песочница: одна ошибка завершает весь прогон (как в V4) — устраивает ли, или показывать все ошибки сразу.
5. Состав колонок таблицы сигнатур и показ «№» (`sig-1`) пользователю.
6. Подтверждение вручную каждой строки галкой — в задании так, но можно дать «подтвердить все».
7. Кто нажимает `[Старт коммерческой эксплуатации]` — партнёр (как в V4) или оператор.
