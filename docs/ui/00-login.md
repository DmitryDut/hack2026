# Вход партнёра

Путь: `/login`. Требования: EMB-1, EMB-2, NFR-4 (+ **новое**, см. «Изменения в SPEC»). Сценарии: S-01, N-01…N-03, N-16, N-17.
Назначение: партнёр попадает в личный кабинет. В прототипе это **мок авторизации PX** — реальной проверки личности нет (вне скоупа, `SPEC.md` §15); вход выдаёт ту же подписанную сессию-токен, что и вход из витрины.

## 0.1 Форма входа
```text
┌──────────────────────────────────────────────────────────────┐
│ Платформа качества связи                                     │
│ Вход для партнёров                                           │
│                                                              │
│ Логин*     [mts-link-1________________]                      │
│ Пароль*    [••••••••__________________]                      │
│            [Войти]                                           │
│                                                              │
│ ──────────────── демо-доступ ────────────────                │
│  MTS Link        mts-link-1      / demo      [Подставить]    │
│  Другой партнёр  other-partner   / demo      [Подставить]    │
│                                                              │
│ Оператор (демо): [Войти как оператор →]                      │
└──────────────────────────────────────────────────────────────┘
```
- Блок «демо-доступ» нужен для показа; в «боевом» виде его скрывают конфигом.
- `[Подставить]` заполняет поля. Учётные записи — `config/accounts.yaml` (логин = `partner_id`, пароль-заглушка).

## 0.2 Поведение
| Действие | Результат |
|---|---|
| верные логин и пароль | создаётся сессия (cookie с подписанным токеном `partner_id + срок`), переход на `/cabinet` |
| неверные | `⚠ Неверный логин или пароль`, поля остаются, пароль очищается |
| открыт `/cabinet` без сессии или с истёкшей | переход на `/login` + `ⓘ Сессия истекла, войдите снова` |
| `[Выйти]` в шапке кабинета | сессия удалена, `/login` |
| вход из витрины PX (iframe) | `/embed?token=…` **заменяет форму входа**: сессия создаётся по токену, переход в кабинет в режиме встраивания (без шапки сайта) |
| плохой токен из витрины | страница ошибки токена (`01-px-showcase.md`, 1.4), форма входа не показывается |
Токен и сессия — один механизм (`SPEC.md` §10): `b64url(payload).b64url(hmac)`, срок по умолчанию 8 часов (в iframe — 1 час).

## 0.3 Роли после входа
| Кто | Куда попадает | Что видит |
|---|---|---|
| партнёр | `/cabinet` | только свои услуги, тарифы, абонентов |
| оператор | `/operator` | все партнёры, журналы, сброс сервиса |
Идентификатор партнёра из сессии подставляется как `X-Partner-Id` во все запросы кабинета; чужие данные недоступны (404).

## Изменения в SPEC, которые требуют эти макеты
(не внесены, ждут вашего решения)
1. Маршруты `/login`, `/logout`, `/cabinet*` (SPEC §7 сейчас перечисляет `/embed` и `/configurator/*`).
2. `config/accounts.yaml` с демо-учётками и сессия по cookie с тем же HMAC-токеном.
3. «Вход оператора» как отдельная кнопка (в SPEC оператор без входа).

## Что проверить при ревью
1. Нужна ли именно форма логин/пароль или достаточно выбора «Войти как…» без пароля.
2. Нужно ли показывать демо-учётки на экране (удобно для показа, но выглядит как «мок»).
3. Нужна ли регистрация нового партнёра с этой страницы (по заданию регистрация — в PX; есть отдельный флоу `06-landing-flow.md`). Предлагаю ссылку «Нет аккаунта? Зарегистрироваться» → `/qos_platform/landing`.
4. Срок сессии и поведение при истечении.
