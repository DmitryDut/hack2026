# Личный кабинет партнёра

Пути: `/cabinet` (главная), `/cabinet/services/new`, `/cabinet/services/{id}` (карточка услуги с вкладками), `/cabinet/offer` (стоимость и предложение), `/cabinet/subscribers`.
Требования: DATA-4…DATA-7, PROC-1…PROC-5, EXP-1, SBX-1…SBX-10, SUB-1…SUB-3, STD-3, NFR-3, NFR-7. Сценарии: S-02…S-08, N-04…N-10, N-13…N-15.
Заменяет прежний «конфигуратор в 5 шагов»: те же шаги процесса (`config/process.yaml`) теперь вкладки карточки **одной услуги**, а общий вид — кабинет со списком услуг, стоимостью и признаком приоритета.

## Каркас
```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ Личный кабинет · MTS Link (mts-link-1)                          [Выйти]     │
│ Услуги │ Стоимость и предложение │ Абоненты │ Журнал                         │
├──────────────────────────────────────────────────────────────────────────────┤
│ {{ содержимое страницы }}                                                    │
└──────────────────────────────────────────────────────────────────────────────┘
```
В режиме встраивания (`?embed=1`, iframe витрины) шапка сайта скрыта, меню кабинета остаётся.
Тарифные названия — как в задании: **Бронза, Серебро, Золото, Платина, Бриллиант**.

## 2.1 Главная: услуги, стоимость, приоритет — `/cabinet`
```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ ⚡ Трафик приоритизирован: 1 из 2 услуг · абонентов с приоритетом: 1         │
├──────────────────────────────────────────────────────────────────────────────┤
│ Мои услуги                                               [+ Добавить услугу] │
│ ┌────────────┬──────┬──────────┬──────┬───────────────┬─────────────────────┐│
│ │ Услуга     │ Сиг. │ Тариф    │ Срок │ Стоимость     │ Статус / приоритет  ││
│ ├────────────┼──────┼──────────┼──────┼───────────────┼─────────────────────┤│
│ │ Link ВКС   │ 4    │ Платина  │ 12 ч │ 30 000 ₽/мес  │ ⚡ Приоритет активен ││
│ │            │      │          │      │               │ до 00:07 [Открыть]  ││
│ │ Link Чаты  │ 1    │ Золото   │ 24 ч │ 17 000 ₽/мес  │ ○ Черновик [Настроить]│
│ └────────────┴──────┴──────────┴──────┴───────────────┴─────────────────────┘│
│                                                                              │
│ Стоимость: запущено 30 000 ₽/мес · в черновиках 17 000 ₽/мес · всего 47 000  │
└──────────────────────────────────────────────────────────────────────────────┘
```
Статусы услуги (из состояния песочницы, `SPEC.md` §8):
| Показ | Состояние |
|---|---|
| `○ Черновик` | `draft` |
| `◐ Тест идёт` | `in_testing` |
| `✗ Тест не пройден` | `failed` |
| `✓ Тест пройден — можно запускать` | `passed` |
| `⚡ Приоритет активен до {{время}}` | `applied`, срок не истёк |
| `⏱ Срок приоритета истёк {{время}}` | `applied`, `expires_at` в прошлом (расчёт при показе; статус в БД не меняется) |
- Верхний баннер появляется, только если есть хотя бы одна услуга с активным приоритетом; иначе: `○ Приоритет пока не включён ни для одной услуги`.
- Стоимость в строке — цена по выбранному тарифу (2.4); если тариф не выбран — «—» и подсказка «Выберите тариф».
- Пусто: «Услуг пока нет. [+ Добавить услугу]».
- Меню «Журнал» — события и внешние вызовы партнёра (только его).

## 2.2 Добавление услуги — `/cabinet/services/new`
Форма строится по схеме `service` (`SPEC.md` §7); минимум полей:
```text
Новая услуга
Название*       [Link Записи___________________]
Описание        [_____________________________ ]
                [Создать и добавить сигнатуры →]   [Отмена]
```
После создания открывается карточка услуги на вкладке «① Данные услуги». Если схему расширили (например, `sla_percent`), поле появится в форме само.

## 2.3 Карточка услуги — вкладка «① Данные услуги» — `/cabinet/services/{id}`
```text
┌ Link ВКС ────────────────────────────────────────────── ⚡ Приоритет активен ┐
│ ① Данные услуги │ ② Тариф и стоимость │ ③ Тестирование │ ④ Запуск и абоненты  │
├───────────────────────────────────────────────────────────────────────────────┤
│ Название*  [Link ВКС_________]   Описание [Видеоконференцсвязь MTS Link____]  │
│                                                         [Сохранить]           │
│                                                                               │
│ Сигнатуры трафика                                       [+ Добавить сигнатуру]│
│ ⓘ Сигнатура — «паспорт трафика»: по адресу, порту и протоколу сеть понимает,  │
│   какие данные ускорять. Несколько портов — несколько строк.                  │
│ ┌──────┬────────────┬───────────────────┬──────┬──────────┬───────────┐      │
│ │ №    │ IPv4       │ URI               │ Порт │ Протокол │           │      │
│ ├──────┼────────────┼───────────────────┼──────┼──────────┼───────────┤      │
│ │ sig-1│ 10.10.1.5  │ vcs.mts-link.ru   │ 443  │ HTTPS    │ [✎] [🗑]  │      │
│ │ sig-2│ 10.10.1.6  │ media.mts-link.ru │ 5004 │ RTP      │ [✎] [🗑]  │      │
│ │ sig-3│ 10.10.1.7  │ api.mts-link.ru   │ 8443 │ HTTPS    │ [✎] [🗑]  │      │
│ │ sig-4│ 10.10.1.8  │ media2.mts-link.ru│ 5005 │ RTP      │ [✎] [🗑]  │      │
│ └──────┴────────────┴───────────────────┴──────┴──────────┴───────────┘      │
└───────────────────────────────────────────────────────────────────────────────┘
```
Форма сигнатуры (по схеме `signature`; открывается в строке или модальном окне):
```text
IPv4*      [10.10.2.10_____]            ← IP-адрес сервера услуги
URI*       [api.mts-link.ru_]           ← доменное имя/URI
Порт*      [8443__]                     ← 1…65535
Протокол*  [HTTPS ▼]                    ← транспорт: RTP, TCP, UDP; прикладной: HTTP, HTTPS, DNS, IMAP, POP3, SSH
           [Сохранить]  [Отмена]
```
Проверки и тексты ошибок (DATA-5, DATA-6): порт вне 1–65535 → «Порт должен быть от 1 до 65535»; неверный IPv4 → «Неверный адрес IPv4»; протокол вне справочника → «Недопустимый протокол»; дубль → плашка «Такая сигнатура уже есть у услуги» (409).
Расширяемость: любое поле, добавленное в схему `signature` (например `ipv6`, `sla_percent` у услуги), появляется в форме и таблице без правки кода (CORE-5; `04-entities-admin.md`).
Блокировки: правка в `in_testing`/`passed`/`failed` → предупреждение «Изменение сбросит тестирование» `[Изменить и сбросить] [Отмена]`; в `applied` кнопки `[✎] [🗑]` недоступны («Приоритет включён; изменения запрещены. Сброс — через оператора»).
Удаление услуги: кнопка в карточке (внизу) → «Удалить услугу и её сигнатуры?».

## 2.4 Вкладка «② Тариф и стоимость» — расчёт по тарифам задания
```text
┌ Link ВКС ─────────────────────────────────────────────────── ○ Черновик ─┐
│ ① Данные │ ② Тариф и стоимость │ ③ Тестирование │ ④ Запуск и абоненты   │
├───────────────────────────────────────────────────────────────────────────┤
│ Выберите тариф качества                                                   │
│ ┌───┬───────────┬────────────┬────────┬───────┬──────────────────────┐   │
│ │   │ Тариф     │ Скорость до│ SLA    │ Коэф. │ Стоимость услуги     │   │
│ ├───┼───────────┼────────────┼────────┼───────┼──────────────────────┤   │
│ │ ( )│ Бронза   │ 10 Мбит/с  │ 99.0 % │ ×1.0  │ 1 000 ₽/мес          │   │
│ │ ( )│ Серебро  │ 30 Мбит/с  │ 99.5 % │ ×1.5  │ 4 500 ₽/мес          │   │
│ │ ( )│ Золото   │ 50 Мбит/с  │ 99.9 % │ ×2.0  │ 10 000 ₽/мес         │   │
│ │ (•)│ Платина  │ 100 Мбит/с │ 99.95 %│ ×3.0  │ 30 000 ₽/мес         │   │
│ │ ( )│ Бриллиант│ 200 Мбит/с │ 99.99 %│ ×4.0  │ 80 000 ₽/мес         │   │
│ └───┴───────────┴────────────┴────────┴───────┴──────────────────────┘   │
│ Срок действия приоритета   [12 ч ▼]   1 ч ×0.15 · 6 ч ×0.6 · 12 ч ×1.0    │
│                                       · 24 ч ×1.7 · 72 ч ×4.0             │
│                                                                           │
│ ┌ Расчёт ─────────────────────────────────────────────────────────────┐   │
│ │ Платина на 12 ч:  100 Мбит/с × 100 ₽ × 3.0 × 1.0 = 30 000 ₽/мес     │   │
│ │ (при 24 ч: × 1.7 = 51 000 ₽/мес; при 1 ч: × 0.15 = 4 500 ₽/мес)     │   │
│ └─────────────────────────────────────────────────────────────────────┘   │
│                                      [Рассчитать заново] [Подтвердить цену]│
└───────────────────────────────────────────────────────────────────────────┘
```
- Таблица тарифов строится из справочника `qos_profile` (только `ACTIVE`): новый тариф появляется в ней сам. Колонка «Стоимость услуги» — цена этой услуги по каждому тарифу (сравнение «что если»).
- Расчёт — по `config/pricing.yaml`: `Мбит/с × 100 ₽ × коэффициент` (задание: «Платина на 12 часов = 30 000 ₽/мес»). Ставку, множители и формулу меняет конфиг (сценарий C-05).
- `[Подтвердить цену]` → цена услуги подтверждена (`assignment_status = confirmed`); вкладка «③ Тестирование» становится доступной. Недоступна, если не выбран тариф или срок.
- Цену по полученному JSON рассчитывает PX (мок, `POST /px/price`); в кабинете показан его ответ.
- Изменение тарифа после подтверждения → «Цена сброшена, подтвердите заново» и сброс тестирования, если оно было.

## 2.6 Вкладка «③ Тестирование» (песочница)
Вид и поведение прежние (автомат, построчная проверка, галки, возврат), в каркасе кабинета:
```text
┌ Link ВКС ──────────────────────────────────────────────── ◐ Тест идёт ──┐
│ ① Данные │ ② Тариф │ ③ Тестирование │ ④ Запуск и абоненты                │
├──────────────────────────────────────────────────────────────────────────┤
│  Черновик ─► [Тест идёт] ─► Пройден ─► Приоритет активен                 │
│ ┌────┬─────────────────────────────┬──────────┬───────────┬─────┬────────┐│
│ │ №  │ Сигнатура                   │ Тариф    │ Результат │Подтв│        ││
│ │ 1  │ 10.10.1.5 vcs…:443 HTTPS    │ Платина  │ ✓ успех   │ [x] │        ││
│ │ 2  │ 10.10.1.6 media…:5004 RTP   │ Платина  │ ✓ успех   │ [x] │        ││
│ │ 3  │ 10.10.1.7 api…:8443 HTTPS   │ Платина  │ … ожидает │ [▒] │[Проверить]│
│ │ 4  │ 10.10.1.8 media2…:5005 RTP  │ Платина  │ … ожидает │ [▒] │[Проверить]│
│ └────┴─────────────────────────────┴──────────┴───────────┴─────┴────────┘│
└──────────────────────────────────────────────────────────────────────────┘
```
- `[Начать тест]` доступна при подтверждённой цене; список услуг для теста — переключатель сверху.
- Ошибка проверки: `✗ ошибка` + «BEARER_TIMEOUT: RTP-поток не отвечает: таймаут установки dedicated bearer для media2.mts-link.ru:5005», статус «✗ Тест не пройден», кнопка `[Вернуться к настройке]` (→ «Черновик», вкладка ①).
- Сброс из-за правки: плашка «⚠ Тестирование сброшено из-за изменения сигнатуры sig-4 (порт 5005 → 5006)» `[Начать тест]`.
- Все строки ✓ и подтверждены → «✓ Тест пройден», кнопка `[К запуску →]`.
- «Журнал» (раскрывающаяся панель) — события `run_started`, `step_checked`, `run_failed`, `run_reset`, `signature_updated`… с понятным текстом (порядок как в `expected_event_log.json`).

## 2.7 Вкладка «④ Запуск и абоненты»
### До запуска (статус `passed`)
```text
Запуск приоритета · Link ВКС                        ✓ Тест пройден
Будет передано в GSMA QoD APIgw (мок):  тариф Платина · 12 ч · сигнатур 4
▸ Показать запрос (JSON)
[Включить приоритет]
```
Ошибка: более 16 уникальных IP → «Допускается не более 16 уникальных IP-адресов (сейчас 18)».

### После запуска — где видно, что трафик приоритизирован (`applied`)
```text
┌ ⚡ Трафик приоритизирован ──────────────────────────────────────────────────┐
│ Тариф: Платина · до 100 Мбит/с · SLA 99.95 %                                │
│ Действует: с 12:07:01 до 00:07:01 (осталось 11 ч 52 мин)                    │
│ Под приоритетом (4 сигнатуры):                                              │
│   10.10.1.5 vcs.mts-link.ru:443 HTTPS    10.10.1.7 api.mts-link.ru:8443 HTTPS│
│   10.10.1.6 media.mts-link.ru:5004 RTP   10.10.1.8 media2.mts-link.ru:5006 RTP│
│ Сессия в сети: qod-session-8f3a2b (GSMA QoD APIgw, мок)   ▸ Ответ APIgw     │
│ Абонентов с подключённой услугой: 1                                         │
│ ⓘ Показывает статус включения в сети по данным APIgw; фактический трафик   │
│   в прототипе не измеряется.                                                │
└─────────────────────────────────────────────────────────────────────────────┘

Подключить услугу абоненту
Номер*  [+7 916 123 00 01____]   [Подключить]
┌────────────────┬──────────┬──────────────────────┐
│ Абонент        │ Статус   │ Приоритет            │
│ +7 916 123 00 01│ AVAILABLE│ ⚡ Трафик приоритизирован│
└────────────────┴──────────┴──────────────────────┘
```
- Признак приоритета виден в **четырёх местах**: баннер и строка услуги на главной (2.1), заголовок карточки услуги, панель выше, карточка абонента (`03-subscriber.md`) и карточка «Партнёр подключён» в витрине (`01-px-showcase.md`).
- Для абонента признак `⚡` показывается при статусе назначения `AVAILABLE`; при `REQUESTED` — `… Включается`.
- Если срок истёк: панель `⏱ Срок приоритета истёк в 00:07:01` серого цвета; для продолжения — вернуть услугу в черновик через оператора и запустить заново (продление не входит в скоуп).
- Сброс «в черновик» — только у оператора (`05-operator.md`).

## Что проверить при ревью
1. **Срок влияет на цену** (решено): коэффициент срока 1 ч 0.15, 6 ч 0.6, 12 ч 1.0, 24 ч 1.7, 72 ч 4.0 — рабочие значения, меняются записью справочника «Duration»; 12 ч = 1.0, поэтому пример задания «Платина на 12 часов = 30 000 ₽/мес» верен. Таблица «Стоимость услуги» в 2.4 показана для выбранного срока (12 ч).
2. **Имена тарифов** по-русски (Бронза…Бриллиант, как в задании); в сидах вариантов они английские — значит, в сиде у `qos_profile.name` будут русские названия.
3. **Вкладки одной услуги вместо мастера из 5 шагов:** порядок ① данные → ② тариф → ③ тест → ④ запуск. Шаги по-прежнему из `process.yaml`.
4. **Индикатор приоритета:** баннер вверху кабинета, статус в таблице, панель в карточке услуги, карточка абонента, витрина PX. Достаточно ли, или нужен отдельный экран «Состояние сети».
5. **Стоимость:** показываем «запущено / в черновиках / всего»; цена за месяц независимо от срока приоритета.
6. «Предложение» и «варианты» (PROC-4) вынесены на отдельную страницу; если варианты не нужны — страница схлопывается до таблицы «итого».
7. Кто нажимает `[Включить приоритет]` — партнёр (как в V4) или оператор.
