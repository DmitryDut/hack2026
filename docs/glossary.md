# Глоссарий

| Термин | Значение |
|---|---|
| **PX** (Partner eXperience) | Витрина и процессы работы с партнёром: регистрация, контракт, оффер, цена, счёт. В демо — мок |
| **QP** (QoS Platform) | QoS-платформа оператора |
| **QoD** (Quality on Demand) | CAMARA API: запрос качества сети по требованию |
| **QoD management** | Наша часть: конфигуратор сервисов партнёра, инвентори, песочница, активация |
| **QoS** | «Приоритетный трафик»: сервис работает быстро даже при перегрузке |
| **QoS-профиль** | Уровень качества: Бронза 10 / Серебро 30 / Золото 50 / Платина 100 / Бриллиант 200 Мбит/с |
| **Приоритет включён / выключен** | Услуга либо включена (⚡ «Трафик приоритизирован»), либо выключена; срока (часов) у приоритета нет — решение 2026-11-03 |
| **Сигнатура** | Паспорт трафика сервиса: `{IPv4, URI, port, protocol}` |
| **Песочница** | Тестовый прогон конфигурации перед запуском в сеть |
| **Applied** | Статус: конфигурация включена через APIgw |
| **Партнёр / Service Provider** | Компания, покупающая приоритет (MTS Link, MAX) |
| **Partner_ID / client_id** | Идентификатор партнёра (`mts-link-1`, `partners-1`) |
| **CAMARA** | Проект Linux Foundation: открытые API операторов |
| **GSMA Open Gateway / APIgw** | Шлюз API операторов; в демо — мок `/mock-gsma/` |
| **SCEF / NEF** | Узлы экспозиции возможностей сети 4G / 5G (интерфейс T8) |
| **PCRF / PCEF** | Политики и их применение в 4G |
| **PFD** (Packet Flow Description) | 3GPP: описание трафика приложения (`flowDescriptions`, `urls`, `domainNames`) |
| **AsSessionWithQoS** | 3GPP T8: подписка приложения на QoS-сессию (`flowInfo`, `qosReference`, `qosDuration`) |
| **QoS-сессия** | CAMARA QoD: назначение профиля на время для потока «устройство ↔ сервер» |
| **App-Flow** | Поток приложения «клиент ↔ сервер», которому дают приоритет |
| **sink** | URL для уведомлений (CloudEvents) у CAMARA |
| **CJ** (Customer Journey) | Оркестратор форм и вызовов в диаграмме задания |
| **RC** (Resource Catalog) | Каталог ресурсов, в том числе QoS-профилей |
| **JSON Schema** | Описание структуры и правил валидации данных; у нас — описание модели |
| **Schema-driven** | Подход: модель, API и UI строятся по схеме, а не по коду |
| **HMAC-токен** | Подписанный токен `partner_id + срок`; подделка не пройдёт проверку |
| **postMessage** | Браузерный механизм обмена сообщениями между iframe и страницей |
| **CSP `frame-ancestors`** | Заголовок, ограничивающий, где можно встраивать страницу |
| **Трассировка** | Журнал реплик флоу (17 сообщений диаграммы) |
| **Инвентори** | Реестр партнёров, сервисов, сигнатур и профилей |
| **CDR / EDR** | Первичные записи об использовании для биллинга (вне скоупа) |
| **rjsf** | Библиотека React-форм по JSON Schema (в ТЗ V2; у нас не используется) |
