# ADR 0003: Конфигурируемое ядро — JSON Schema в БД, процесс и цена в YAML

**Контекст:** главный критерий — после демо организаторы просят «поменяйте вот это» и меряют время и стоимость [S, T 5]. Вариант ТЗ 2 (schema-driven) предлагает модель/API/UI из JSON Schema [V2].
**Решение:**
- Типы сущностей описываются **JSON Schema, хранящейся в БД** (`entity_defs`); данные — JSON в `entities`. Универсальный CRUD валидирует по схеме. Правка схемы через админку действует сразу, без рестарта.
- Формы и таблицы UI рисует наш небольшой рендерер по схеме (вместо React/rjsf, ADR 0001 не меняется).
- Процесс партнёра (шаги, порядок), формула цены и маппинг JSON для PX — `config/*.yaml`; правка файла + перезапуск (или перечитывание по запросу).
- Новые зависимости: `jsonschema`, `pyyaml`.
**Почему не код:** каждая правка требовала бы цикла разработки; не low-code платформа: достаточно схем и двух-трёх конфигов.
**Границы:** служебные сущности (TestRun, TestStep, EventLog, NetworkRequest, TraceEntry) и автомат песочницы — в коде; конфигурируются данные и справочники.
**Последствия:** валидация схем и конфигов при сохранении/старте с понятной ошибкой; тесты проверяют, что смена схемы меняет поведение без правок кода; рендерер ограничен набором типов (analysis §8).
