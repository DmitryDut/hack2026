# ADR 0003: Конфигурируемое ядро (YAML)

**Контекст:** главный критерий задания — стоимость и скорость изменений; «процесс, модель данных, API и UI могут конфигурироваться динамически без полного цикла разработки» [T 5].
**Решение:** меняющиеся бизнесом вещи живут в `config/*.yaml`: справочники (протоколы, QoS-профили), процесс партнёра (статусы и переходы), правила цены, маппинг JSON для PX. Код — маленький универсальный движок. Добавляем зависимость `pyyaml`.
**Почему не БД-админка или low-code:** для PoC файл проще: правится в редакторе, версионируется в git, нет UI редактора и миграций.
**Границы:** справочники читаются при старте (перезапуск применяет правки). Поля сущностей (модель) в первой итерации фиксированы в коде; расширение через `extra: JSON`-поле сигнатуры/сервиса с описанием в YAML — задача T-010, если хватит времени.
**Последствия:** валидация YAML при старте с понятной ошибкой; тесты проверяют, что смена конфига меняет поведение.
