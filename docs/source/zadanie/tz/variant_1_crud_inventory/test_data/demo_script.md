# Демо-сценарий для варианта 1 (репетировать перед демо)

Продолжительность: 5 минут. Перед началом: БД инициализирована сидом (`seed.json`), приложения запущены.

## Шаг 1 (30 сек). Список партнёров
- Открыть главную страницу → список партнёров.
- **Видно:** MTS Link (mts-link-1, active). Больше никого.

## Шаг 2 (1 мин). Создание сервиса и сигнатур
- Создать сервис: имя «Link Чаты», описание «Чаты MTS Link».
- В сервисе «Link ВКС» (из сида) добавить сигнатуру:
  - ipv4 `10.10.2.10`, uri `api.mts-link.ru`, port `8443`, protocol `HTTPS`.
- **Видно:** у «Link ВКС» теперь 3 сигнатуры.

## Шаг 3 (30 сек). Валидация (провокация)
- Попытаться добавить сигнатуру с портом `70000`.
- **Видно:** форма отклонена, ошибка о недопустимом порте, запись не появилась.
- (Дубликат для A3: повторно отправить сигнатуру `10.10.2.10 / api.mts-link.ru / 8443 / HTTPS` → HTTP 409.)

## Шаг 4 (1 мин). Назначение профиля
- В сервисе «Link ВКС» назначить QoS-профиль `PLATINUM`, Duration `12H`, статус `confirmed`.
- (Уже создан сидом — если создаёте заново, подтвердить.)

## Шаг 5 (1 мин). Экспорт и витрина
- Открыть `GET /api/v1/partners/mts-link-1/export` → JSON.
- **Видно:** структура как в `expected_export.json`: 1 сервис, 3 сигнатуры, Platinum, 12H.
- Открыть `/mock-px?partner_id=mts-link-1`.
- **Видно:** продуктовое предложение «Link ВКС», Platinum 100 Мбит/с, 12 ч, цена 100 × 100 ₽/мес × 3.0 = **30 000 ₽/мес**.

## Шаг 6 (30 сек). Удаление (A7)
- Удалить сервис «Link Чаты».
- **Видно:** сервис исчез из списка; в export-JSON его нет (обновить страницу витрины).

## Чек-лист соответствия критериям
| Критерий | Шаг демо |
|---|---|
| A1 (порт 70000) | Шаг 3 |
| A3 (дубликат → 409) | Шаг 3 |
| A4 (сценарий проходит) | Шаги 1–6 |
| A5 (структура export) | Шаг 5 |
| A6 (витрина с ценой) | Шаг 5 |
| A7 (каскадное удаление) | Шаг 6 |

A2 проверяется отдельно: POST сигнатуры с protocol `SMTP` → отклонено.
