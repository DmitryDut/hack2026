# ТЗ для хакатона по вайбкодингу (3 часа) — 5 вариантов

**Кейс:** «Создание прототипа процесса управления сервисами партнера (QoS-платформа / QoD management)», МТС, блок 2 хакатона.
**Полное ТЗ кейса:** `../confluence_export/ТЗ_Прототип_QoD_management.md` (+ материалы в `../confluence_export/`).
**Сводный анализ вариантов:** `../Варианты_ТЗ_хакатон_3ч.md`.

Каждый вариант — самодостаточное ТЗ в своём каталоге: можно скопировать `ТЗ.md` целиком в ИИ-ассистент и строить по разделам. Тестовые данные лежат рядом в `test_data/` и подключаются по ссылкам из ТЗ.

## Каталоги

| Каталог | Вариант | Что демонстрирует | Ключевой критерий успеха |
|---|---|---|---|
| `variant_1_crud_inventory/` | CRUD-инвентори | Справочники + CRUD + валидация + JSON для PX | A1–A7: валидация отклоняет мусор, экспорт совпадает с эталоном |
| `variant_2_schema_driven/` | Schema-driven | Модель/API/UI из JSON Schema, меняется конфигом | A2–A4: смена требований без кода, новая сущность через админку |
| `variant_3_ai_agent/` | AI-агент | Чат + tool calls, сырая спецификация → справочники | A1–A8: запись только через инструменты с подтверждением |
| `variant_4_sandbox_simulator/` | Песочница | Автомат Draft→Testing→Passed→Applied, мок APIgw | A1–A9: контроль изменений, полный журнал, session_id |
| `variant_5_px_showcase_iframe/` | Витрина + iframe | Сквозной флоу 17 сообщений, HMAC-токен, postMessage | A1–A9: трассировка покрывает все 17 реплик, токен сквозной |

## Структура каждого каталога

```
variant_N_name/
├── ТЗ.md          # полное ТЗ: стек, модель, требования F*, демо, критерии A*
└── test_data/     # сиды, эталоны, сценарии, контракты моков
```

## Как выбирать вариант

- **Гарантированное демо / слабое знакомство с фронтендом** → вариант 1 или 4 (данные предзаполнены, логика детерминирована).
- **Показать соответствие духу кейса** («скормить агенту в сыром виде», LLM на UC-диаграмме) → вариант 3.
- **Показать соответствие букве ключевого требования** (конфигурируемость без разработки) → вариант 2.
- **Сильная команда, опыт с iframe/CORS** → вариант 5.
- Комбинации: 1 — фундамент для 3 и 5; 4 стыкуется с 1 (ввод + песочница).

## Общие правила всех ТЗ

- Ограничение: 3 часа вайбкодинга, результат — работающее демо.
- Всё, что нельзя сделать за 3 часа — мокается (ядро сети, реальный PX, реальная авторизация).
- Онбординг/контракт/базовый оффер — out of scope (по кейсу уже пройдены).
- Критерии приёмки — отдельный раздел «Как мы поймём, что результат достигнут»: каждый пункт = наблюдаемое действие + ожидаемый результат.
